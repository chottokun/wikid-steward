## 1. 静的解析＆CLIコア機能（Python/uv）のチェックリスト

### 1.1 堅牢型再リンク（`relinker.py`）
- [ ] **多層トークナイズ（表現保護）の実装**

    - [ ] 既存の `[[WikiLink]]` および `[表示名](URL)` 形式のリンク

    - [ ] Mermaid ブロック（`` ```mermaid ... ``` ``）
    - [ ] LaTeX ブロック数式（`$$...$$`）およびインライン数式（`$...$`）
    - [ ] GFM画像記法（`![fig](assets/{slug}/fig.png)`）および `<img>` タグ
- [ ] **大見出し（`##`）セクション単位の「ファーストヒット置換」**
  - 同一ドキュメント内に複数登場する用語について、各大見出しセクション（`##`）ごとに、**最初にヒットした1箇所のみ**が `[[WikiLink]]` に置換されているか？
  - セクションを跨いだ場合は、新しいセクションで再度最初の1回のみ置換されるか？
- [ ] **名前空間に隔離されたアセットの物理配置**
  - 一次情報（`_raw/`）から抽出したアセット画像が、`wiki/assets/{slug}/` フォルダに自動分類・格納されているか？
  - 生成された Markdown 内に、**`![fig1.png](assets/{slug}/fig1.png)`** の形式でパスが書き込まれているか？
  - 異なる資料から抽出された同じファイル名（例: `fig1.png`）が、お互いに上書きされずに個別の `{slug}` ディレクトリ配下で衝突を物理的に完全に防止して共存できているか？

### 1.2 「## 📝 手書きメモ」の絶対死守（ガードレール）

### 1.3 `wikid-steward lint`（セルフヒーリング＆監査）

- [ ] **OKF v0.2 フロントマターの動的自動初期化**
  - 生成されたスタブに、必要最小限のメタデータ（`type: Concept`、`status: draft`、および Actor 規約に準拠した `generated: { by: "wikid-steward/linter", at: ISO8601 }`）が正しく付与されているか？
- [ ] **脚注（Footnotes）と YAML の静的整合性スキャン**

## 2. LLM/VLM 自律連携（`compile-stub`）のチェックリスト

- [ ] **逆合成起動のためのバックリンク数 $N$ 閾値制限**
  - 設定ファイル（`config.yaml`）で定義した閾値 $N$ 件（デフォルト：`3`、設定：`retro_compilation.min_backlinks`）以上のユニークな被リンク（同じドキュメント内からは1件のみカウント）がスタブページに集まるまで、自動逆合成（LLMの起動）が安全に保留（`status: draft` の維持）されるか？
- [ ] **循環コピー汚染（ハルシネーションの連鎖）の100%遮断**
  - バックリンクの文脈（前後数行）を逆引きスキャンして LLM プロンプトを組み立てる際、**「`generated.by: 'wikid-steward/auto-compiler'` を持ち、かつ `verified`（人間による審査）がないページ」が、コンテキストソースから完全に除外されているか？**
  - スキャンのソースは、人間による審査済み（`verified`あり）または `status: stable` の信頼性の高いドキュメントのみに厳格に制限されているか？
- [ ] **多言語統制（日本語への統一）**
  - 文脈ソースに英語・日本語が混在していても、`config.yaml` で指定された `llm.target_language: "Japanese"` に基づき、LLMが生成するMarkdownの本文はすべて日本語に翻訳・統一されて出力されるか？
- [ ] **二段階昇格（フォルダ移動）ライフサイクル**
  - LLMによる自動逆合成が完了、あるいは人間がレビューを完了したタイミングで、ファイルが `wiki/stubs/` から本来のルーティング先本番フォルダ（例: `wiki/concepts/`）へと自動的に移動（昇格）されるか？
